# Подключение телефона к собственному серверу

[English](PAIRING.md) | **Русский**

Простая пошаговая инструкция: [README.ru.md](README.ru.md). Здесь приведены подробности сети, идентичности и расширенной настройки.

Carriex может работать по IP со своим TLS-сертификатом. Регистрировать домен, покупать сертификат, устанавливать его в систему или ставить другое приложение на телефон не требуется. Сервер создаёт постоянный ключ подписи и самоподписанный сертификат. QR-код/текст содержит **открытый сертификат**, адрес и отображаемое имя. Телефон сохраняет ключ сервера и проверяет его при каждом подключении. HTTPS и WSS шифруют соединение; отдельный ключ Android Keystore аутентифицирует ID устройства.

## Домашний компьютер Windows

В папке сервера один раз установите зависимости (Python 3.11+):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Укажите `CARRIEX_HOST`, `CARRIEX_PORT` и `CARRIEX_SERVER_NAME` в корневом `.env`, затем запустите `start-server.bat`. Нужен действительный IPv4 компьютера из `ipconfig`. Без настроек запуск может использовать последний сохранённый адрес или запросить его в интерактивном терминале. Однократное переопределение:

```powershell
.\start-server.bat --address https://192.168.1.20:8443 --name Home
```

Порт прослушивания по умолчанию следует опубликованному URL (443 без явно заданного порта) или `CARRIEX_PORT`. Разрешите входящий TCP на этом порту в брандмауэре только для нужных сетей. Оставьте терминал работающим. Windows использует многопоточный сервер разработки Flask без отладки; он подходит для разработки и тестирования. Для развёрнутой службы используйте Docker/Gunicorn ниже.

1. Локально откройте `.carriex-server\pairing.html`. Терминал выводит полный путь. Страница показывает QR-код и выделяемый текст подключения; язык выбирается через **English / Русский**.
2. На телефоне выберите **Сканировать QR-код сервера**, разрешите камеру и нажмите **Сохранить сервер**. Либо выберите **Импортировать текст подключения**, вставьте весь JSON со страницы или из `pairing.json`, нажмите **Проверить**, затем **Сохранить сервер**.
3. Нажмите **Подключиться** рядом с сохранённым сервером. Добавьте сервер один раз на каждом телефоне.
4. Покажите собеседнику на том же сервере QR-код **Мой ID**. Он выбирает **карандаш → Сканировать QR-код** для открытия чата. **Проверить ID собеседника** внутри чата сравнивает ID с QR-кодом собеседника. Чат показывает состояние подключения и восстановления связи.

Сканер встроен в Carriex. Текстовый импорт не требует камеры. Для дополнительной открытой копии файлов при запуске через .bat/.sh/Python укажите путь в `CARRIEX_PAIRING_EXPORT_DIR`, например `./pairing-export`. При каждом запуске `pairing.html`, `pairing.png`, `pairing.json` обновляются и там, и в `.carriex-server`. HTML нужен PNG рядом. Обычный запуск создаёт отсутствующий каталог экспорта. Если по пути находится файл или каталог расположен внутри закрытого каталога идентичности, запуск завершается ошибкой. `--check-config` только показывает путь; `--pair-only` создаёт его и файлы. Терминал отдельно обозначает **private identity directory** и **public pairing export directory**.

Импортируйте только данные, полученные непосредственно от владельца по доверенному каналу. Подмена исходного QR-кода/текста позволяет подменить сервер. Отображаемый отпечаток позволяет сверить ключ с владельцем. Набор подключения — открытая информация, а не пароль приглашения: регистрация доступна каждому, кто может обратиться к серверу и доказать владение ключом.

## Доступ из другой сети

Добавление сервера устанавливает доверие, но опубликованный адрес должен оставаться доступным:

- **Один Wi-Fi:** укажите локальный IP домашнего компьютера, например `https://192.168.1.20:8443`. Закрепление DHCP на маршрутизаторе сохраняет его постоянным.
- **Мобильная сеть / другая домашняя сеть:** укажите публичный IP маршрутизатора и внешний порт, например `https://203.0.113.10:8443` (только пример из документации). Пробросьте этот TCP-порт на локальный IP и порт компьютера и разрешите его в брандмауэре. Проверяйте через мобильные данные: некоторые маршрутизаторы не обращаются к собственному публичному адресу из LAN.
- **CGNAT или запрет входящих у провайдера:** домашний проброс может не работать. Получите доступный публичный IP у провайдера или перенесите сервер на доступный узел, например VPS. Телефонам нужен только Carriex. При смене публичного IP обновите опубликованный адрес и повторно импортируйте данные; необязательный динамический DNS позволяет сохранить постоянное имя.

Порт `--address` — тот, к которому обращаются телефоны. Локальный порт следует ему, если не задан `--port` или `CARRIEX_LISTEN_PORT` для отображения маршрутизатора. Если порты различаются, запуск явно показывает оба. Не используйте `0.0.0.0` и `localhost` в данных для другого устройства. Для эмулятора Android на компьютере сервера укажите `https://10.0.2.2:8443`.

## Сохранение и изменение ключа

Защищайте `.carriex-server` и безопасно резервируйте его. **Никогда не передавайте `server-key.pem`**. Открыты только `pairing.json`, `pairing.png`, `pairing.html`; для просмотра на другом компьютере копируйте HTML вместе с PNG. Весь каталог идентичности публиковать нельзя. Запуск ограничивает доступ учётной записью запуска и SYSTEM в Windows; последующие запуски выполняйте от той же записи.

Ключ используется повторно после перезапуска. Сертификат действует год и обновляется при запуске, если осталось менее 30 дней, с тем же ключом. Перезапускайте до истечения: непрерывно работающий процесс не обновляет сертификат по таймеру. Телефоны принимают действительный новый сертификат с тем же ключом без повторного добавления, но проверка дат и запрошенного имени/IP остаётся.

Для смены адреса отредактируйте `.env`, перезапустите с тем же каталогом идентичности и передайте обновлённые данные подключения. Запись адреса в сертификате пересоздаётся с прежним ключом. Одновременно поддерживается только один опубликованный origin аутентификации. Старые адреса на телефонах можно забыть. При переносе на другой компьютер безопасно перенесите закрытый каталог и ограничьте там права.

Если сохранённый ключ пропал, запуск останавливается вместо незаметной замены. Восстановите резервную копию. Для намеренно новой идентичности нужен новый пустой `--data-dir`; телефоны должны явно **Забыть** старый сервер перед импортом другого ключа по тому же адресу. Ошибка TLS никогда не обновляет закреплённый ключ.

`--pair-only` создаёт/обновляет файлы без слушателя. `--check-config` проверяет и выводит настройки без изменения файлов идентичности. `--config path/to/file.env` выбирает другой файл. Приоритет: CLI → окружение оболочки → `.env` → прежние сохранённые настройки. Относительные пути идентичности считаются от рабочей папки; .bat/.sh переходят в собственную папку. Поиск `.env` выше по дереву не выполняется. Значения буквальные; подстановки переменных и исполнение команд не поддерживаются.

`--init-config` добавляет недостающие HOST/PORT/имя на основе сохранённого адреса или явного `--address`, не меняя существующие значения и не создавая ключи. Старый `CARRIEX_PUBLIC_URL` поддерживается вместо HOST/PORT; не задавайте обе формы одновременно. Старый `CARRIEX_TLS_PORT` переопределяет порт прослушивания. Предупреждение браузера при открытии HTTPS API ожидаемо: доверие настроено внутри Carriex. Установка сертификатов в систему/браузер не требуется.

## Docker / Linux

Самостоятельный paired Compose завершает TLS напрямую и использует постоянный том идентичности. В PowerShell:

```powershell
# First edit .env as described in README.md.
docker compose -f compose.paired.yaml up --build -d
docker compose -f compose.paired.yaml logs server
New-Item -ItemType Directory -Force pairing-export
docker compose -f compose.paired.yaml cp server:/var/lib/carriex/pairing.html ./pairing-export/
docker compose -f compose.paired.yaml cp server:/var/lib/carriex/pairing.png ./pairing-export/
docker compose -f compose.paired.yaml cp server:/var/lib/carriex/pairing.json ./pairing-export/
```

Откройте `pairing-export/pairing.html`. Внешний порт по умолчанию — 8443; меняется через `CARRIEX_PORT` в `.env`. Сохраняйте том `server-identity`; `docker compose down -v` используйте только для намеренного удаления идентичности. Безопасно резервируйте закрытый том. Обычный `docker compose` включает этот paired-вариант; `compose.proxy.yaml` — отдельная старая схема с HTTP-прокси. Внутри Docker слушатель остаётся на 8443, настроенный порт хоста отображается автоматически.

Для автоматического экспорта вместо трёх `docker compose cp` создайте каталог на хосте, укажите абсолютный путь в `CARRIEX_PAIRING_EXPORT_DIR` и используйте оба Compose-файла:

```powershell
docker compose -f compose.paired.yaml -f compose.pairing-export.yaml up --build -d
```

Каталог хоста должен существовать и быть доступен для записи пользователю `carriex` контейнера. Дополнительный файл монтирует только открытый каталог экспорта; закрытая идентичность остаётся в отдельном томе. Открывайте `pairing.html` из указанной папки. При последующих `logs`, `up`, `down` указывайте оба Compose-файла.

Для обычного Linux установите `python -m pip install '.[server]'` и запустите `python -m src.pairing --address https://YOUR_REACHABLE_IP:8443`. Linux использует один Gunicorn worker со 100 потоками. Сохраняйте один worker/экземпляр: реестр устройств, сеансы и живые WebSocket локальны для процесса. Очереди зашифрованных сообщений сохраняются в SQLite; повторная аутентификация автоматически регистрирует прежний ID ключа. Для интернета нужны эксплуатационные ограничения частоты и мониторинг.
