# Безопасность

[English](SECURITY.md) | **Русский**

Carriex аутентифицирует устройства подписями P-256 в обмене подтверждениями и краткоживущими bearer-сеансами. Сервер хранит открытые ключи, но не закрытые ключи устройств. Отправка и входящие привязаны к аутентифицированному ID. Точный протокол и границы модели угроз: [AUTHENTICATION.ru.md](AUTHENTICATION.ru.md).

Для удалённого использования обязательны HTTPS/WSS. `CARRIEX_ALLOW_INSECURE_HTTP=1` предназначен только для локальной разработки. Доверяйте заголовкам прокси только за изолированным доверенным TLS-прокси. Запуск с QR-подключением использует постоянный самоподписанный TLS-ключ. Телефоны доверяют открытому ключу из QR-кода/текста, отдельно проверяя действующие сроки сертификата и имя узла. Получайте исходный набор по доверенному каналу: его подмена позволяет подменить сервер. Защищайте закрытый каталог идентичности и делайте резервные копии. См. [PAIRING.ru.md](PAIRING.ru.md).

Регистрация открытая: владение ключом не устанавливает личность человека и не означает одобрение администратором. Отзыва и администрирования нет. Очереди шифротекста и открытые наборы X3DH сохраняются в SQLite; bearer-сеансы и регистрации сокетов остаются локальными для процесса. Используйте один worker и подходящие входные ограничения.

Необязательные фоновые проверки Android используют постоянные хешированные отзывные учётные данные только для собственного количества ожидающих сообщений. Они не могут отправлять, скачивать и подтверждать сообщения, но раскрывают владельцу количество и изменения поступления; срок по умолчанию — семь дней. Android шифрует их ключом Keystore. См. [NOTIFICATIONS.ru.md](NOTIFICATIONS.ru.md).

Android проверяет подписанные предварительные ключи X3DH и подпись P-256, связывающую ключ шифрования с полным ID контакта. Сверяйте ID непосредственно с нужным человеком: ID первого контакта, полученный только от сервера, не устанавливает личность. Изменение закреплённого ключа шифрования отклоняется. Сервер хранит только открытые предварительные ключи и непрозрачный шифротекст, атомарно выдаёт одноразовые ключи и ограничивает частоту запросов. Израсходованные открытые ключи удаляются; монотонные ревизии публикаций не дают восстановить их повторной отправкой. Подтверждение публикации начинает отсчёт хранения закрытых ключей. Ограничения сеансов, квоты по контактам, постраничные входящие, зашифрованные запросы и серверные лимиты ограничивают злоупотребление хранилищем. Резервный режим без одноразового ключа требует явного включения. Обновляйте оба телефона и сервер вместе. См. [X3DH.ru.md](X3DH.ru.md).

Android v3 добавляет классический Double Ratchet: развитие ключей сообщений, DH-переходы, ограниченные по сроку/числу пропущенные ключи и транзакционное состояние, переживающее перезапуск. Оба телефона должны обновиться; старые сеансы и конверты v2 с фиксированным ключом не используются повторно. API предварительных ключей совместим; сервер не получает секреты ratchet. Защита израсходованных ключей и восстановление после пассивной компрометации зависят от новых незатронутых DH-вкладов, случайности и удаления. Контроль устройства, компрометация идентичности, сохранённая открытая история, оставшиеся пропущенные ключи и старые снимки базы остаются рисками. Постквантовая защита и независимый аудит не заявляются.

Подтверждения доставки остаются состояниями, сообщёнными сервером. Необязательные отчёты о прочтении на Android по умолчанию отключены; они раскрывают метаданные просмотра серверу и отправителю и не являются криптографическим доказательством чтения. Сообщения карантина и скрытой доставки нельзя отметить прочитанными. В группах остаются только подтверждения доставки.

Изменения состава групп подписаны и связаны хешами. Создатель-администратор приглашает, удаляет участников и подписывает общие изменения названия. Приглашённые проверяют приглашения или включают автоматическое принятие в настройках Android; участники могут выйти. Права администратора не передаются. Для каждой эпохи состава используются новые цепочечные ключи и ключи подписи каждого отправителя, распространяемые через аутентифицированное личное шифрование. Сервер отклоняет старые эпохи и запрещает доступ удалённым участникам. Названия и состав видны серверу; секреты отправителей он не хранит.

История событий ограничена реальными периодами участия устройства, включая выход и повторное вступление. Приглашение не даёт истории. Новый участник начинает со своего приглашения и точного вступления, подтверждённого подписью постоянного администратора, если прямое изменение «приглашение → вступление» недоступно. Клиент не распространяет ключи отправителя для неподтверждённого состава. Продолжающие участие устройства хранят старые ключи получения только на срок очереди для задержанной доставки. Протокол, квоты и ограничения: [GROUPS.ru.md](GROUPS.ru.md).

Необязательная статистика хранит почасовые агрегаты количества, размеров и времени. В таблицы измерений не добавляются ID, содержимое или учётные данные, но агрегаты раскрывают активность, а запись SQLite создаёт нагрузку. По умолчанию сбор отключён. Отдельный просмотрщик доступен только локально и только для чтения; публичного API статистики у сервера нет. См. [STATISTICS.ru.md](STATISTICS.ru.md).

Сообщайте об уязвимостях непублично через вкладку GitHub Security, если включена закрытая отправка отчётов. Иначе свяжитесь с сопровождающим через его профиль GitHub. Не публикуйте чувствительные данные в issues. Указывайте затронутую версию и шаги воспроизведения.

Исправления безопасности предназначены для последнего выпуска; поддержка старых версий не гарантируется.
