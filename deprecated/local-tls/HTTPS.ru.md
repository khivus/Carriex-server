# Настройка локального HTTPS — архив

[English](HTTPS.md) | **Русский**

Это историческая схема; актуальная — [QR-подключение](../../PAIRING.ru.md). В описанной версии приложение использует HTTPS и 443 по умолчанию, а Python backend на 5000 — только HTTP. Отдельное развёртывание добавляет Caddy с частным CA для HTTPS/WSS, не публикуя backend 5000.

1. Закрепите LAN IP сервера, например DHCP-резервацией. Добавьте `SERVER_ADDRESS=192.168.1.10` в `.env`, заменив адрес на используемый телефонами. Без схемы, пути и порта. Сохраните остальные настройки.
2. Разрешите входящий TCP 443 из LAN в брандмауэре. Проброс интернета не нужен.
3. Если работает HTTP-схема, остановите `docker compose down` без `-v`. В исторической версии это перезапускает сервер и очищает очередь в памяти. Запустите TLS:

   ```sh
   docker compose -f compose.https.yaml up --build -d
   docker compose -f compose.https.yaml logs -f caddy
   ```

4. После запуска Caddy экспортируйте только открытый CA-сертификат:

   ```sh
   docker compose -f compose.https.yaml cp caddy:/data/caddy/pki/authorities/local/root.crt ./carriex-local-ca.crt
   ```

Выведите SHA-256 отпечаток на сервере через OpenSSL:

   ```sh
   openssl x509 -in carriex-local-ca.crt -noout -fingerprint -sha256
   ```

Или JDK в Windows:

   ```powershell
   & 'C:/Program Files/Android/Android Studio/jbr/bin/keytool.exe' -printcert -file carriex-local-ca.crt
   ```

5. Передайте `carriex-local-ca.crt` каждому телефону по доверенному каналу, например USB. Не экспортируйте и не передавайте закрытый ключ CA. В соответствующей версии приложения укажите точный IP/имя и `443`, оставьте **Use HTTPS**, выберите **Local server certificate** и импортируйте сертификат. Сверьте отпечаток с сервером до **Trust CA**.
6. Нажмите **Connect** на обоих телефонах. CA доверен только этому адресу и порту. Проверка цепочки и имени/IP остаётся для HTTPS/WSS. При смене адреса/порта нужно одобрить CA для нового адреса. Смена CA требует нового импорта.

Сохраняйте том `caddy_data`: в нём закрытый ключ CA и выданные сертификаты. Защищайте хост и копии: владелец ключа CA может выдать себя за сервер. `docker compose down -v` допускается только при намеренной замене CA. Во всех дальнейших командах используйте `-f compose.https.yaml`: это отдельный файл, не дополнение к compose.yaml.

Проверьте с компьютера через curl:

```sh
curl --cacert carriex-local-ca.crt https://192.168.1.10/health
```

Ожидается `status: alive`. Не используйте `-k` и не отключайте проверку. Другой IP/hostname должен отклоняться, если не включён в сертификат. Caddy автоматически обновляет локальные сертификаты. Архивный backend сохраняет один Gunicorn worker, поскольку очереди и подключения локальны для процесса.

## Границы безопасности

Схема защищает канал до сервера через явно одобренный CA. Она не исправляет неаутентифицированные ID архивного сервера, не добавляет авторизацию и не аутентифицирует обмен ключами чата. Это отдельные задачи до рабочего защищённого мессенджера. Само наличие TLS не делает публикацию этого архивного сервера в недоверенных сетях безопасной.

Исходный compose.yaml в этой версии остаётся явной HTTP-схемой разработки. HTTPS не понижается до HTTP автоматически. Сохранённые настройки остаются; существующие установки вручную переводятся на HTTPS и 443.

Для публичного домена замените `tls internal` на выдачу общедоверенного сертификата и настройте доступ DNS/ACME. Удалите локальное переопределение CA в приложении для использования системного доверия Android.
