# Сервер Carriex

[English](README.md) | **Русский**

Запустите собственный сервер чатов Carriex и подключите телефоны по QR-коду. Регистрировать сайт и устанавливать на телефоны дополнительные приложения не требуется.

Необязательная [статистика для практической работы](STATISTICS.ru.md) сохраняет почасовые измерения после перезапуска. Включите `CARRIEX_STATISTICS=1` и запустите `python -m src.statistics serve` для локальной панели и экспорта CSV/JSON.

[Уведомления Android по количеству сообщений](NOTIFICATIONS.ru.md) обращаются прямо к серверу: интервал по умолчанию — 15 минут, можно задать свой. Внешний push-провайдер не нужен.

[Групповые чаты](GROUPS.ru.md) поддерживают принятие приглашений, постоянного администратора, удаление участников и добровольный выход. Каждое изменение состава обновляет ключи всех текущих отправителей; распространение идёт через существующие зашифрованные личные сеансы.

## Хранение сообщений

Сервер сохраняет непрозрачные зашифрованные сообщения в `messages.sqlite3` в закрытом каталоге данных: по умолчанию `.carriex-server`, в Docker с прямым TLS — `/var/lib/carriex` в постоянном томе. Ожидающие сообщения переживают перезапуск. По умолчанию они истекают через 30 дней; срок задаётся `CARRIEX_MESSAGE_TTL_SECONDS`. Очередь получателя вмещает до 1000 сообщений. Шифротекст удаляется только после подтверждения его ID получателем или истечения срока. Само получение HTTP-ответа или отправка по WebSocket его не удаляют. Отправитель запрашивает статусы своих сообщений; получатель может подтвердить с `report_delivery: false`, очистив очередь без раскрытия доставки. Сохранённой историей владеет телефон. При пересоздании контейнера сохраняйте закрытый том данных.

## 1. Укажите адрес и порт

Файл настроек — **`.env` в этой папке**, рядом с README. Если его нет, скопируйте `.env.example` под именем именно `.env`, а не `.env.txt`. Откройте текстовым редактором:

```dotenv
CARRIEX_HOST=192.168.0.34
CARRIEX_PORT=8443
CARRIEX_SERVER_NAME='Carriex-server'
```

- Замените пример IP на IPv4 сетевого интерфейса компьютера (Wi-Fi/Ethernet). В Windows он показан командой `ipconfig`.
- `CARRIEX_HOST` содержит только IP или имя узла, без `https://`, пути и порта.
- `CARRIEX_PORT` — порт подключения телефонов и открываемый порт компьютера. Используйте `8443` или `443`. При 443 адрес — `https://192.168.0.34`, при 8443 — `https://192.168.0.34:8443`.
- `CARRIEX_SERVER_NAME` — отображаемое на телефонах имя.
- Дополнительно задайте `CARRIEX_PAIRING_EXPORT_DIR` для открытых копий `pairing.html`, `pairing.png` и `pairing.json`. В Docker нужен дополнительный файл Compose; см. [PAIRING.ru.md](PAIRING.ru.md).

Сохраните файл и перезапустите сервер. Запуск проверяет настройки, выводит адрес и порт прослушивания, обновляет QR-код и текст. При необходимости смена адреса обновляет сертификат. **Закрытый ключ сервера остаётся прежним**, поэтому редактирование настроек не подменяет доверенный сервер. После смены адреса/порта импортируйте обновлённый QR-код на телефоны и забудьте старую запись.

Старые `HOST` / `PORT` относятся к прежнему варианту с HTTP-прокси и не настраивают сервер с QR-подключением. Используйте три параметра `CARRIEX_...` выше.

## 2. Выберите один способ запуска

Все три способа используют один `.env`.

### Windows: двойной щелчок по .bat

Установите Python 3.11 или новее. Один раз откройте PowerShell в этой папке:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Затем дважды щёлкните **start-server.bat** или выполните:

```powershell
.\start-server.bat
```

Оставьте терминал открытым; Ctrl+C останавливает сервер. Запуск непосредственно в Windows подходит для разработки и домашнего тестирования; для развёрнутой службы предпочтителен Docker.

Проверка настроек без запуска:

```powershell
.\start-server.bat --check-config
```

### Linux / macOS: shell-скрипт

Файл `.bat` непосредственно в Linux не работает. Используйте включённый shell-скрипт. Однократная установка из этой папки:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install '.[server]'
```

Запустите и оставьте терминал открытым:

```sh
sh start-server.sh
```

Остановка — Ctrl+C. Проверка: `sh start-server.sh --check-config`. Linux/macOS используют Gunicorn. Если ОС запрещает обычному процессу порт 443, используйте отображение портов Docker или 8443; запускать всё приложение от root ради порта не нужно.

### Docker: Windows, Linux или macOS

Установите Docker с Docker Compose, запустите Docker и откройте терминал в папке:

```sh
docker compose up --build -d
docker compose logs -f server
```

Сервер работает в фоне; Ctrl+C закрывает только просмотр журнала. После изменения `.env` примените `docker compose up -d`: простой `restart` новые настройки контейнера не загружает. После обновления кода используйте `docker compose up --build -d`.

Остановка:

```sh
docker compose down
```

**Не добавляйте `-v`**: это удалит том с идентичностью сервера. Docker автоматически отображает `CARRIEX_PORT` компьютера на внутренний 8443. Внутренний порт не ограничивает порт, используемый телефонами.

`compose.paired.yaml` по-прежнему поддерживается. Прежняя схема только с HTTP-прокси теперь явно запускается через `compose.proxy.yaml`.

## 3. Откройте QR-код и подключите телефоны

**Запуск через .bat / .sh:** откройте `.carriex-server/pairing.html` в браузере. Полный путь также выводится в терминале.

**Docker:** скопируйте только открытые файлы подключения:

```sh
docker compose cp server:/var/lib/carriex/pairing.html ./pairing.html
docker compose cp server:/var/lib/carriex/pairing.png ./pairing.png
docker compose cp server:/var/lib/carriex/pairing.json ./pairing.json
```

Откройте `pairing.html`; PNG должен лежать рядом. После изменения настроек скопируйте файлы снова: ранее экспортированная страница сама не обновляется. На странице есть выбор **English / Русский**.

На каждом телефоне:

1. Откройте Carriex и выберите **Сканировать QR-код сервера**.
2. Отсканируйте код, проверьте адрес, нажмите **Сохранить сервер**, затем **Подключиться**.
3. Без камеры выберите **Импортировать текст подключения** и вставьте всё содержимое `pairing.json`.
4. Покажите собеседнику **Мой ID**. Он выбирает **карандаш → Сканировать QR-код**, чтобы начать чат. В существующем чате **Проверить ID собеседника** сравнивает ID беседы с QR-кодом на его телефоне.

## Не удаётся подключиться?

- **Одна сеть Wi-Fi:** используйте локальный адрес компьютера и разрешите входящий TCP на `CARRIEX_PORT` в его брандмауэре. `localhost` на другом телефоне не подходит.
- **Другая сеть или мобильные данные:** локальный адрес `192.168...` недоступен из интернета. Нужен доступный публичный IP и проброс порта маршрутизатора на компьютер. При CGNAT запросите публичный IP у провайдера или используйте доступный VPS. См. [сетевую настройку](PAIRING.ru.md#reaching-the-server-from-another-network).
- **Не работает 443:** проверьте строку `Listening:` при запуске, занятость порта другим процессом и правило брандмауэра. Linux может ограничивать низкие порты. Запуск использует порт URL/настроек, а не молча подставляет 8443.
- **Ошибка подлинности сервера:** проверьте часы телефона и импортируйте текущий адрес подключения. Перед удалением старой доверенной записи сверяйте намеренную смену ключа с владельцем.
- **Ошибка конфигурации:** запуск указывает проблемный параметр. Поддерживаются имена в кавычках. Значения буквальные; команды оболочки в файл не помещайте.

## Сохраняйте эти файлы в безопасности

Создавайте резервную копию каталога `.carriex-server` или тома Docker `server-identity`. Никогда не передавайте `server-key.pem`. Передавайте только HTML, PNG или JSON подключения по доверенному каналу. Если ранее сохранённый ключ пропал, запуск останавливается вместо незаметной замены.

Хранилища обычного запуска и Docker раздельные; переключение режима не переносит идентичность автоматически. Для прежнего ключа перенесите закрытое хранилище безопасно. См. [расширенную настройку](PAIRING.ru.md), [аутентификацию](AUTHENTICATION.ru.md) и [документацию разработчика/API](DEVELOPMENT.ru.md).

Bearer-сеансы находятся в памяти. После перезапуска телефоны аутентифицируются снова с тем же ID устройства. Очереди шифротекста и открытые предварительные ключи X3DH сохраняются в SQLite. Для X3DH обновите оба телефона и сервер. Чтобы получить первое сообщение без подключения, получатель должен хотя бы раз опубликовать предварительные ключи. См. [X3DH, Double Ratchet и ограничения безопасности](X3DH.ru.md). Формат Android v3 использует классический Double Ratchet; оба телефона должны обновиться вместе. API предварительных ключей совместим и не хранит секреты ratchet.

Неизвестные отправители попадают на телефоне в ограниченное зашифрованное хранилище запросов на переписку. Списки контактов и блокировок передаются серверу для резервирования входящей вместимости. Ревизии публикаций, подтверждённые сроки хранения ключей, сроки сеансов и квоты требуют совместного обновления сервера и телефонов. Резервный режим без одноразовых ключей по умолчанию отключён; его можно явно разрешить в **Безопасность чатов**.
