# Статистика для практической работы

[English](STATISTICS.md) | **Русский**

Сбор необязательный, по умолчанию отключён. Включите в `.env` и перезапустите через `start-server.bat`, `./start-server.sh` или Docker Compose:

```dotenv
CARRIEX_STATISTICS=1
CARRIEX_STATISTICS_RETENTION_DAYS=30
```

Обычные скрипты запуска также принимают `--statistics` / `--no-statistics` с приоритетом над `.env`. `--check-config` показывает режим. Хранение — от 1 до 365 дней.

Во втором терминале из папки сервера:

```powershell
# Dashboard at http://127.0.0.1:8766, updated every five seconds:
.\.venv\Scripts\python.exe -m src.statistics serve
# Terminal report:
.\.venv\Scripts\python.exe -m src.statistics show
# Hourly observations for a report/spreadsheet:
.\.venv\Scripts\python.exe -m src.statistics export --format csv --output experiment.csv
.\.venv\Scripts\python.exe -m src.statistics export --format json --output experiment.json
```

Linux/macOS использует `.venv/bin/python`. Свой каталог сервера и период:

```powershell
.\.venv\Scripts\python.exe -m src.statistics --data-dir D:\CarriexData --days 7 serve --port 8766
```

Просмотрщик также читает `CARRIEX_IDENTITY_DIR` из `.env`. Он открывает базу только для чтения и слушает только `127.0.0.1`, отдельно от публичного сервера. Публичного адреса статистики/администрирования и дополнительных данных для телефона нет. Страница даёт JSON/CSV; для удалённого сервера используйте SSH-туннель или экспорт на самом сервере. Переключатель **English / Русский** меняет подписи и формат чисел, не содержимое экспорта и не имена показателей API.

Для Docker задайте те же переменные `.env`, пересоздайте сервер, затем:

```sh
docker compose exec -T server python -m src.statistics --data-dir /var/lib/carriex show
docker compose exec -T server python -m src.statistics --data-dir /var/lib/carriex export --format csv > experiment.csv
```

## Хранение и интерпретация

Почасовые агрегаты UTC сохраняются в `statistics_hourly` и `statistics_meta` существующей закрытой `messages.sqlite3`, по умолчанию `.carriex-server/messages.sqlite3`. Старые интервалы удаляются при сборе/запуске. Отключение сбора прекращает новые измерения, сохраняя ещё не истёкшую историю; экспорты и сохранённые страницы не удаляются.

| Показатель | Значение |
|---|---|
| `messages.accepted` | Новые сохранённые сообщения без точных повторов |
| `messages.duplicate_submissions` | Повторная отправка уже принятого ID |
| `messages.size_bytes` | Байты UTF-8 непрозрачного поля шифротекста, включая hex Android |
| `messages.socket_handoffs` | Передача нового сообщения в подключённый сокет, а не доставка получателю |
| `messages.acknowledged` | Первое подтверждение получателем, без повторов |
| `messages.delivery_receipts` | Подтверждения с запросом видимого отправителю статуса доставки |
| `messages.ack_delay_ms` | От принятия до подтверждения, включая ожидание без подключения, опрос и обработку клиентом |
| `messages.quarantined` | Удаление из очереди без подтверждения доставки |
| `messages.expired` | Удаление очереди по TTL |
| `messages.rejected.*` | Отказы из-за размера, вместимости или маршрута |
| `prekeys.published`, `prekeys.claimed` | Загруженные/запрошенные открытые OPK; запрос не доказывает установление сеанса |
| `prekeys.publication_retries`, `prekeys.claims_without_opk`, `prekeys.rate_limited` | Повторы публикации, исчерпание и ограничения частоты |
| `http.METHOD.endpoint.Nxx_ms` | Время обработки HTTP сервером по маршруту и классу ответа |
| `websocket.opened`, `websocket.closed` | Регистрация/удаление аутентифицированных сокетов |

У каждого показателя есть число измерений, сумма, минимум, максимум и среднее. Суммы счётчиков считают события/элементы. Средние времени/размера описывают наблюдаемые значения; их суммы — не длительность эксперимента. CSV содержит строку на показатель/час. Текущая длина очереди, байты и число OPK — снимки, а не исторические максимумы. Блокировка сообщения не равна подтверждению получателем, а подтверждение — чтению. Время HTTP не включает передачу по сети и отдачу ответа. Сервер не знает длительности клиентского шифрования/расшифровки и длины открытого текста.

Сборщик не добавляет в статистику тела, шифротекст, ID устройств/сообщений, IP, учётные данные или ключи. Обычные очереди/каталоги продолжают хранить нужные для работы данные. Агрегаты раскрывают активность; обычные access-журналы сервера отдельны. Сбор добавляет записи SQLite и влияет на время обработки.

## Воспроизводимый эксперимент

1. Запишите версии приложения/сервера, устройства, сеть, начало/конец UTC, режим и срок хранения. Экспортируйте исходный уровень и сравнивайте накопленные счётчики с ним.
2. Отправьте известное число коротких сообщений при обоих подключённых устройствах. Сравните принятие, передачи в сокет, подтверждения, размеры и время обработки. Повторите с длинным текстом ниже 90 КиБ UTF-8.
3. Отключите получателя, отправьте сообщение, проверьте очередь и подключите снова. Наблюдайте рост задержки подтверждения из-за ожидания без связи.
4. Перезапустите сервер и убедитесь в сохранении измерений. Повторы и исчерпание ключей проверяйте на изолированных тестовых идентичностях; запросы OPK не равны завершённым X3DH.
5. Экспортируйте CSV/JSON и сообщайте только реальные наблюдения. Сравнивайте одинаковые режимы сбора. Среднее/минимум/максимум — описательные наблюдения, не процентили и не аудит безопасности. Сборщик не создаёт результаты эксперимента за вас.
6. Включите уведомления по количеству на телефоне получателя, сверните Carriex и отправьте известное число сообщений. Сравните настроенный интервал, наблюдаемую задержку уведомления, количество ожидающих сообщений, число GET счётчика и задержку подтверждения после открытия приложения. Повторите с оптимизацией заряда и без неё, с разными интервалами. Метрика `http.GET.notifications.pending_count.2xx_ms` измеряет обработку сервером, а не планирование Android или полную задержку уведомления.
