# Интеграционные тесты

[English](README.md) | **Русский**

Запускайте из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Для каждого теста pytest создаёт отдельный процесс Flask на свободном порту `127.0.0.1`, ждёт `/health` и останавливает процесс после теста. Вручную сервер запускать не требуется. HTTP и WebSocket обращаются к одному серверу через реальные сокеты. Тесты проверяют коды/JSON, не импортируя приложение и не обращаясь к состоянию памяти.

Новый процесс изолирует очереди и подключения. При ошибке запуска выводится журнал; запуск и запросы имеют тайм-ауты. Зависимости — в корневом `requirements.txt`.

Фикстуры сообщений создают ключи и выполняют реальный обмен запросом подтверждения и подписью. `raw_client` используется для отклонений/атак; обхода аутентификации нет. Покрыты поддельные подписи/отправители, повторы и конкурентные повторы, привязка к origin сервера, сроки сеансов, неразрешённые WebSocket upgrade, владение входящими и восстановление после перезапуска.

`test_pairing.py` вызывает поставляемый CLI в подпроцессе, использует временные каталоги идентичности, проверяет постоянство ключей и обновление, созданные файлы и реальный HTTPS/WSS. Проверяется отклонение самоподписанного сертификата обычным системным доверием. Межъязыковой Android-тест дополнительно декодирует PNG QR и использует настоящий Kotlin-клиент для аутентификации и доставки.

`test_config.py` проверяет общий `.env`, приоритет CLI/окружения, неверные настройки, обновление QR без смены ключа и реальные TLS-слушатели. Проверка порта 443 пропускается только при занятости или запрете ОС. Настройки изолированы во временных файлах; рабочий `.env` оператора не используется.

При запущенном Docker команда `python tests/check_docker_pairing.py` дополнительно проверяет обычный Compose: создаёт уникальный тестовый проект, публикует только loopback, проверяет HTTPS и аутентифицированный WSS, меняет временный `.env` и подтверждает сохранение ключа. После удаляет только собственные контейнеры/том. Обычный pytest Docker не требует.

`test_config_migration.py` и `test_config_migration_cli.py` проверяют категории,
точные резервные копии, буквальные/дополнительные/прежние значения, личные
комментарии, BOM/переводы строк, будущие шаблоны, повторные запуски, файлы только
для чтения и одновременное редактирование. Проверки CLI подтверждают, что просмотр
настроек, неверные лимиты и отсутствие gevent не переписывают настройки и не
создают идентичность. `test_bootstrap.py` моделирует обновление зависимостей и сбои
загрузки без изменения установленных пакетов. Docker-проверка также выполняет
описанную явную миграцию файла хоста через временный каталог с доступом на запись.
